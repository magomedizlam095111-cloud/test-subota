🐚 UNIX Терминал

Навигация и файловая система

pwd

Показать текущую директорию (Print Working Directory)

ls [-la]

Список файлов. -l подробный, -a скрытые файлы

cd [путь]

Перейти в директорию. cd .. на уровень вверх, cd ~ в домашнюю

mkdir [-p]

Создать папку. -p создаёт промежуточные папки автоматически

# Примеры
pwd
ls -la
cd ~/projects
mkdir -p src/components/utils

Работа с файлами и правами

touch файл

Создать пустой файл или обновить timestamp

cp [-r]

Копировать. -r рекурсивно для папок

mv

Переместить или переименовать файл/папку

rm [-rf]

Удалить. Осторожно -rf удаляет без подтверждения

chmod/chown

Изменить права и владельца. Пример: chmod +x script.sh

cp config.yaml backup/
mv old_name.txt new_name.txt
rm -rf node_modules
chmod 644 index.html
chown user:group project/

Конвейеры, вывод и справка

cat/head/tail

Вывод содержимого. head -n 5 первые 5 строк, tail -f следить за логами

grep [шаблон]

Поиск текста в файлах/выводе. -i без учёта регистра, -r рекурсия

| > >>

| конвейер, > перезаписать файл, >> добавить в конец

man / --help

Встроенная документация. man ls или git commit --help

cat error.log | grep "ERROR" > critical.log
tail -f /var/log/syslog
ls -l | sort -k5 -rn | head -n 10

🔹 Git & GitHub

Инициализация и конфигурация

git init

Создать новый пустой репозиторий в текущей папке

git clone [url]

Склонировать удалённый репозиторий локально

git config

Настроить имя, email, редактор по умолчанию

git config --global user.name "Ivan Petrov"
git config --global user.email "ivan@example.com"
git config --global core.editor "vim"
git config --global init.defaultBranch main

Индекс, коммиты и история

git status

Текущее состояние: изменённые, новые, удалённые файлы

git add [файл|.]

Добавить в индекс (staging area)

git commit [-m]

Сохранить снимок. -m "сообщение" без открытия редактора

git log [--oneline]

История коммитов. --graph --all для визуализации веток

git diff

Показать изменения: рабочие файлы vs индекс / индекс vs HEAD

git status
git add src/app.js styles.css
git commit -m "fix: корректная обработка 404"
git log --oneline --graph --decorate

Ветки и слияние

git branch [-a]

Список локальных веток. -a показывает удалённые

git switch / checkout

Переключиться на ветку. switch — современный аналог checkout

git merge [ветка]

Слить указанную ветку в текущую

git rebase [ветка]

Переместить коммиты поверх указанной ветки (линейная история)

git branch feature/auth
git switch feature/auth
# ... работа ...
git switch main
git merge feature/auth
# или
git rebase main  # в ветке feature/auth

Отмена изменений

git restore [файл]

Вернуть файл в состояние последнего коммита (рабочая область)

git restore --staged

Убрать из индекса, не меняя рабочую копию

git commit --amend

Дополнить последний коммит (сообщение или файлы)

git reset [--soft/mixed/hard]

Сдвинуть HEAD. --hard удаляет изменения, используйте аккуратно

git restore index.html
git restore --staged logo.png
git commit --amend -m "fix: обновить логотип"
git reset HEAD~1  # отменяет коммит, оставляя файлы в индексе

🌐 GitHub Интеграция

Удалённые репозитории и синхронизация

git remote add origin [url]

Привязать удалённый репозиторий с псевдонимом origin

git push [-u] origin [ветка]

Отправить изменения. -u запомнит связь веток для последующих git push

git pull

fetch + merge. Скачивает и сразу сливает изменения

git fetch

Только скачивает изменения, не меняет рабочую директорию

git remote add origin git@github.com:user/repo.git
git push -u origin main
git fetch origin
git checkout -b feature/x origin/feature/x
SSH vs HTTPS: Для работы без ввода пароля настройте SSH-ключ: ssh-keygen -t ed25519 → добавьте публичный ключ в GitHub → git remote set-url origin git@github.com:user/repo.git

Коллаборация и Pull Request

  1. Fork репозитория на GitHub
  2. git clone своей копии
  3. Создать ветку: git checkout -b feat/my-change
  4. Внести правки, закоммитить и отправить: git push origin feat/my-change
  5. На GitHub нажать Compare & pull request
  6. Добавить описание, теги, ревьюеров → Create pull request
Синхронизация с оригиналом: 
git remote add upstream https://github.com/original/repo.git
git fetch upstream
git switch main
git merge upstream/main

💡 Советы и лучшие практики

  • Используйте .gitignore для исключения node_modules/, .env, dist/, IDE-файлов.
  • Пишите осмысленные сообщения коммитов. Рекомендуется формат тип(область): описание (Conventional Commits).
  • Часто пушьте небольшие изменения. Это упрощает ревью и откат.
  • Не коммитьте в main напрямую. Работайте в ветках.
  • Проверяйте git status перед add и commit.
  • Для отмены только локальных экспериментов используйте git stash.
  • Никогда не используйте git push --force в общих ветках. Если нужно — --force-with-lease.
Как учиться дальше? В терминале всегда доступны: man [команда], [команда] --help, git help [subcommand]. Для Git: git help workflows, git help everyday.
